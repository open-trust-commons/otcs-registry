# Interface domain: Repair

*Status: EXPERIMENTAL capability domain — NOT a normative specification (docs/interface-model.md §2). Adding required semantics here is a proposal, not an edit.*

**Purpose.** Restoring environmental capacity after damage: incident response, reconciliation, rollback, uncertainty-resolution, human review queues.

**Wire format.** None specified in v0.1.

**Open questions.** Likely to need several distinct interfaces (detection-to-queue, queue-to-resolution, resolution-to-capacity-credit) — deliberately unsplit until a real repair system registers.

**Formalization trigger.** The first registrant with functions.repair as its principal contribution.
