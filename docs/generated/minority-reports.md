# When reviewers disagree

*Version 0.1 · Status: EXPERIMENTAL*

**This registry does not force one synthesis.** When credible reviewers disagree, the disagreement is published rather than resolved by editorial fiat.

---

## 1. What a published analysis can contain

```text
Majority synthesis
Project A response
Project B response
Minority analysis        ← equal standing, not an appendix
Unresolved questions
```

## 2. The outcome most systems cannot express

> **The source facts are agreed. Their architectural interpretation remains disputed.**

**That is a successful result, not a failure to conclude.**

Manufacturing a single "Commons conclusion" where none exists would be exactly the synthetic consensus the evidence model refuses everywhere else ([EVIDENCE-MODEL.md](evidence-model.md) §7).

## 3. What a minority report has to meet

The same schema, the same disclosure ([ANALYST-DISCLOSURE.md](analyst-disclosure.md)), and the same source anchoring as the majority analysis.

> **It is not a comment.** It is a co-equal record that happens to have fewer signatories.

It carries its own status, its own review date and its own supersession chain.

## 4. How it is displayed

Both appear **at the same visual level.**

**The interface may not present the majority as the finding and the minority as an objection to it.** Layout is an argument; putting one view in smaller type below the other decides the question the document deliberately left open.

## 5. Unresolved questions

Every analysis carries an explicit `unresolved_questions` list.

> **An analysis with none is suspect** — either the subject was trivial, or the review was incurious.
