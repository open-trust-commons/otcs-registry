## Current integration constraints

The candidate pins eight historical project manifests: `abt`, `ktp`, `ktp-demo`, `ex-gatekeeper`, `ex-ledgerline`, `ex-mendwell`, `ex-watchtower` and `lifecycle-fixture`. The pinned upstream tree contains those paths plus `registry/projects/otcs-ai-use/otcs.yaml`. Therefore the candidate inventory must not be described as covering all current upstream objects. Updating the list alone would not supply a governance decision or fresh transition authority.

The two trees also use `0.2` differently. Upstream `schemas/project-manifest.schema.json:17` accepts both `0.1` and `0.2`; `MIGRATIONS.md:27` associates `v0.2.0` with the OTCS-0003 coordinate-layer trial, explicitly pending its decision. Candidate `index.mjs:75` routes `0.2` only through the proposed `owner_source` stage and its separate schema. The shared version token does not establish representation compatibility. This map records the collision without allocating a release number, changing either proposal's status or choosing a migration policy.

The validation caches change execution cost, not requirement status. `canonical-json.mjs:39` reuses successful strict-parser work only for identical text while returning freshly parsed values; `index.mjs:32` rereads the legacy lock and schema bytes before reusing a byte-identical compiled set. Neither cache stores an authority or admission decision. Their implementation bytes remain part of the construction toolchain identity. See `VALIDATION-CACHES.md`, `json-cache.node.mjs` and `checker-cache.node.mjs`.

## Ratification and feature activation

Section 8 of [the current amendment](amendment-rights-retention.md) separates the
exact normative package proposed for ratification from the composed evidence
required before each feature may be enabled. The 54 rows below retain their
requirements and enforcement layers; they describe candidate support, not a
requirement to implement or activate every optional path before a vote. Any
permission within the vote must still have fixed terms. An expressly deferred
operation remains disabled pending its applicable normative decision and full
activation evidence. Every enabled path retains all applicable rights, storage,
lifecycle, controlled-copy and atomicity obligations. The five mandatory consent
fields are unchanged. This map allocates no release version, grants no authority
and records no feature activation.

## Changes material to the earlier map

Rows 43, 44 and 54 must no longer describe external-text excerpts, historical logo display or additional word-mark display as entirely absent. Those are now bounded composed paths, with different suppression rules for optional reference selections and mandatory retained snapshot members.

Rows 51 and 52 must no longer describe all independent domain vectors as missing. The six listed vector families provide bounded cross-implementation comparisons; their uncovered domains and branches remain explicit. Row 51 also needs the current upstream inventory mismatch, not the old claim that eight objects exhaust the current registry.

Rows 19, 29, 30 and 53 must distinguish implemented observation evidence from the deliberately closed publication path. A verified document and authenticated observer testimony do not activate an observed listing or supply its rendered notice/removal workflow.

Historical page, contributor-content, view-registration and directory-scan composition also update rows 11, 16, 17, 21, 23, 34–42, 45 and 50. These additions preserve the central outstanding boundary: no supplied component provides complete atomic admission and global publication/reconciliation under ratified, independently established governance.
